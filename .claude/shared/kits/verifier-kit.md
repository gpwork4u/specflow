# verifier kit — 報告/日誌範本 + 收尾流程（按需 Read，非常駐）

> verifier.md 在通過 hard gate 後產報告/日誌時才 Read。

---

## 1. 三維度檢查指令

### Completeness
```bash
gh issue list --label "feature" --milestone "{SPRINT}" --state open --json number,title
gh issue list --label "bug" --milestone "{SPRINT}" --state open --json number,title
gh issue list --label "qa" --milestone "{SPRINT}" --state open --json number,title
grep -c "^- \[" specs/features/f*.md                              # spec AC 數
jq '[.suites[].specs[].tests[]] | length' test/reports/playwright.json   # 已執行 test 數
jq '.stats.expected' test/reports/playwright.json                  # 通過數
```
檢查：所有 feature issue 有 merged PR｜所有 AC 有對應 Playwright test｜所有 bug 關閉｜Sprint sub-tasks 完成。

### Correctness
```bash
grep -hE "POST|GET|PUT|PATCH|DELETE" specs/features/*.md
grep -r "router\.\|app\." dev/src/routes/ --include="*.ts" --include="*.js"
grep -r "INVALID_INPUT\|UNAUTHORIZED\|DUPLICATE" specs/features/ dev/src/
jq '[.suites[]?.specs[]? | {title,file,status:(.tests[]?.results[]?.status//"unknown")}] | map(select(.status!="passed"))' test/reports/playwright.json
```
檢查：API path / status code / error code / data model field 與 spec 一致｜business rules 都有實作。

### Coherence
```bash
ls -R dev/src/
( cd dev && npm run lint ) 2>&1 || true
```
檢查：目錄結構符合 `specs/overview.md`｜命名慣例一致｜error handling pattern 一致｜需 auth 的 endpoint 都有 auth｜無 dead code/重複邏輯。

## 2. 驗證報告 `specs/verify-sprint-{N}.md`

```markdown
# Sprint {N} 驗證報告
## 總結：🟢 PASS / 🟡 WARNING / 🔴 FAIL

## 1. Completeness
| 項目 | 狀態 | 詳情 |
|------|------|------|
| Feature issues 全部關閉 | ✅ | {N}/{N} |
| Bug issues 全部關閉 | ✅ | {N}/{N} |
| AC 覆蓋率 | ✅ | {N}/{N} tests 通過 (playwright.json) |
| QA issue 關閉 | ✅ | |
缺失：（如有）

## 2. Correctness
| API endpoints / Error codes / Data model / Business rules 一致 | ✅ | {N}/{N} |
偏差：（如有）

## 3. Coherence
| 目錄結構 / 命名 / Error handling / Linter | ✅ | |
問題：（如有）

## Issues 發現
### CRITICAL（必修）/ WARNING（建議）/ SUGGESTION（可改善）
```

結果處理：
- **PASS/WARNING** → `gh issue comment {sprint_issue} --body "✅ Sprint {N} 三維度驗證通過"` → 執行 §3 收尾
- **FAIL** → `gh issue comment {sprint_issue} --body "🔴 Sprint {N} 驗證失敗，需修復後重新驗證。詳見 specs/verify-sprint-{N}.md"`（不執行收尾）

---

## 3. Sprint 工作日誌 + 收尾（僅 PASS/WARNING）

### 日誌 `specs/logs/sprint-{N}-log.md` 區塊
基本資訊（Sprint/Milestone/日期/Epic/Sprint Issue 連結）｜完成功能（每 feature: Issue/PR/Branch/Scenarios + 1-2 句簡述）｜UI 設計（Design Issue/PR/元件數，無則省）｜測試結果（Unit/E2E 通過失敗表 + QA Issue/Test PR/Report）｜Bug 修復表（無則「本 sprint 無 bug」）｜三維度驗證表｜數據摘要（Feature/PR/Commit/Bug/AC/Test 數）｜所有相關 PR 表｜footer `*Generated by SpecFlow — {timestamp}*`。

要求：所有連結可點擊（完整 URL）｜格式嚴格一致｜資料從 GitHub API 取得（不依賴本地狀態）｜commit 進 repo。

### 收尾 bash

```bash
mkdir -p specs/logs
SPRINT="{current_sprint}"; SPRINT_NUM={N}
MILESTONE_URL=$(gh api repos/{owner}/{repo}/milestones --jq '.[] | select(.title=="'"$SPRINT"'") | .html_url')
FEATURES=$(gh issue list --label "feature" --milestone "$SPRINT" --state closed --json number,title,url)
BUGS=$(gh issue list --label "bug" --milestone "$SPRINT" --state closed --json number,title,url)
PRS=$(gh pr list --state merged --search "milestone:\"$SPRINT\"" --json number,title,url,mergedAt)
# 依上述格式寫 specs/logs/sprint-{N}-log.md

git add specs/logs/
git commit -m "docs: sprint ${SPRINT_NUM} work log

Refs #{sprint_issue_number}"
git push
gh issue comment {sprint_issue} --body "📋 工作日誌：specs/logs/sprint-${SPRINT_NUM}-log.md"

# 關 sprint issue + milestone（PASS/WARNING 才執行；FAIL 不關）
# 為什麼這裡關：下一 sprint 啟動時 sprint-test workflow 用 milestone 排序挑「最早未關閉 Sprint」當 current；沒關舊的會卡住下一輪
gh issue close {sprint_issue} --reason completed
REPO=$(gh repo view --json nameWithOwner --jq '.nameWithOwner')
MILESTONE_NUM=$(gh api "repos/$REPO/milestones?state=open" --jq '.[] | select(.title=="'"$SPRINT"'") | .number' | head -1)
[ -n "$MILESTONE_NUM" ] && gh api -X PATCH "repos/$REPO/milestones/$MILESTONE_NUM" -f state=closed && echo "✅ Milestone $SPRINT 已關閉"

# Archive 測試報告（入版控做歷史追溯，不留 raw artifacts）
mkdir -p "specs/logs/sprint-${SPRINT_NUM}-artifacts"
[ -f test/reports/playwright.json ] && cp test/reports/playwright.json "specs/logs/sprint-${SPRINT_NUM}-artifacts/"
[ -d test/reports/playwright-report ] && cp -R test/reports/playwright-report "specs/logs/sprint-${SPRINT_NUM}-artifacts/"
git add "specs/logs/sprint-${SPRINT_NUM}-artifacts/" 2>/dev/null || true

# 終極清乾淨 + 重置 state 為下一 sprint 準備
bash .claude/scripts/local-checks.sh cleanup
bash .claude/scripts/state.sh set lane_closed '{"feature":false,"design":false,"qa":false,"bug":false}'
bash .claude/scripts/state.sh set sprint_test_outcome 'null'
bash .claude/scripts/state.sh phase "phase-7-next" "等待使用者確認下一個 sprint 或 release"
```
